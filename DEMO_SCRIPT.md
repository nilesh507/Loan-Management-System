# CreditSea recording script (target: 4 minutes 50 seconds)

Record one continuous desktop-browser walkthrough at `http://localhost:3000` with MongoDB, API, and frontend already running. Keep the browser at about 1440 × 900 so the queue actions are visible. Practice once before recording; the time marks are targets. Show the address bar briefly at the start and avoid showing a terminal or `.env` file.

## Before recording

1. Run `npm ci`, copy `.env.example` to `.env`, set a new `JWT_SECRET`, start MongoDB, run `npm run seed`, and run `npm run dev` (or `npm run build && npm run start`). Confirm the API health endpoint returns `database: connected`.
2. Use the included real, one-page synthetic document: `demo/synthetic-salary-slip.pdf`. It contains only fictional text.
3. This script uses the **new** borrower `asha.creditsea.demo.20261009@example.com` so the seeded borrower's existing loans do not affect the recording. Before the take, confirm that email is unused. If repeating a take, increment the final two digits of the email, for example `...10@example.com`.
4. The executive accounts are `sales@creditsea.demo`, `sanction@creditsea.demo`, `disbursement@creditsea.demo`, `collection@creditsea.demo`, and `admin@creditsea.demo`. Their shared development password is `CreditSea@123`.
5. Use UTRs `CSDEMO20261009A` and `CSDEMO20261009B` only once. If repeating the payment portion, change the date/letter suffix so both UTRs remain globally unique. Use the actual recording date in the payment-date field.
